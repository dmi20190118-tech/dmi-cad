# 개발 목적과 사용자 교육 기준

기준일: 2026-10-24

## 개발 목적

제품 설계와 금형·가공 준비 과정에서 형상을 여러 번 다시 입력하거나, 도면·NC·지시서의 변경 내용이 서로 어긋나는 일을 줄인다.
하나의 프로젝트를 중심으로 설계자가 형상을 만들고, 가공 담당자가 경로와 조건을 준비하고, 현장 작업자가 필요한 지시를 이해하도록 연결한다.

목표는 전문적인 통합 3D 설계·제조 프로그램이다. 현재 파일 뷰어·수동 지시서 시제품이 이 목표를 이미 달성한 것은 아니다.

## 대상 사용자와 해야 할 일

| 사용자 | 주요 작업 | 설명에 꼭 포함할 정보 |
|---|---|---|
| 처음 쓰는 설계자 | 파일 열기, 화면 조작, 스케치·치수·모델링 | 시작 위치, 기준면, 선택 대상, 결과 확인 |
| 금형 설계자 | 파팅, 코어/캐비티, 슬라이드/리프터 | 이형 방향, 분할 조건, 언더컷, 간섭 |
| CAM 담당자 | 셋업, 공구, 경로, NC, 조건표 연결 | 단위, 좌표, 컨트롤러, 포스트와 검증 범위 |
| 현장 작업자 | 지시서 확인, 셋업·공구·원점 확인 | 작업 순서, 치수·공차, 주의사항, 불일치 대응 |
| 관리자 | 배포·환경·양식·조건표 관리 | 버전, 권한, 출처, 변경과 복구 |

아직 개발되지 않은 기능의 절차는 설계안으로 표시하고 실제 사용 안내와 분리한다.

## 기능별 도움말의 고정 형식

각 기능은 아래 내용을 갖춘다.

1. **무엇을 하는가:** 기능의 목적을 일상 언어로 설명한다.
2. **언제 쓰는가:** 앞뒤 작업과 연결된 구체적인 상황을 든다.
3. **무엇이 필요한가:** 파일, 형상, 좌표계, 단위, 조건표와 권한을 명시한다.
4. **어디서 시작하는가:** 메뉴·버튼 이름과 화면 위치를 실제 제품과 맞춘다.
5. **어떻게 하는가:** 한 단계에 한 행동, 입력값의 의미와 예시, 클릭/터치/단축키를 설명한다.
6. **어떤 결과가 나오는가:** 성공 상태와 산출 파일을 보여준다.
7. **잘못됐으면 어떻게 하는가:** 증상, 원인, 해결과 데이터 복구 방법을 제공한다.
8. **무엇은 못 하는가:** 지원하지 않는 형식·범위·정확도와 전제 조건을 설명한다.
9. **어떻게 되돌리는가:** 취소·원본 보존·변경 취소 절차를 설명한다. 미구현이면 명시한다.
10. **어느 버전인가:** 제품 버전·빌드, 설명 확인일, 예제 파일과 영상 버전을 기록한다.

전문 용어는 첫 등장 때 뜻을 풀고 용어집으로 연결한다. 경고는 단순한 빨간 창보다 '무엇이 / 왜 / 어떻게 수정할지'를 담아야 한다.

## 제공할 자료

- 시작하기: 설치부터 첫 결과까지 이어지는 짧은 안내.
- 사용자 안내서: 작업별 설명, 용어, 문제 해결.
- 기능별 정밀 도움말: 입력·선택·좌표·계산·옵션·한계 설명.
- 예제 파일: 공유 가능한 비고객 자료, 기대 결과와 단위 포함.
- 화면 안 도움말: 툴팁, F1/도움말, 관련 항목 링크. 아직 제품 연결은 개발 과제.
- 짧은 작업 영상: 실제 배포 빌드에서 시작·행동·결과를 보여주는 자막 영상.
- 변경 안내: 추가·변경·미지원·알려진 문제와 문서 영향.
- 개발·확장 문서: 공통 데이터와 영역 간 의존성, 개발 단계.

현재 작성된 것은 Markdown 문서와 영상 구성안이다. PDF 책자, 제품 내 도움말 연결, 실제 교육 영상은 별도 제작해야 한다.

## 개발과 문서의 완료 기준

새 기능은 ① 목적·작업 순서 ② 조작·화면 ③ 구현·검증 순서로 개발한다.
그 과정에서 도움말 초안을 같이 작성하고 구현 결과에 맞춰 수정한다.

사용 가능으로 공개하기 전에:
- 실제 메뉴와 설명이 일치하는지 확인한다.
- 예제 입력으로 기대 결과가 재현되는지 확인한다.
- 누락·오입력·취소·실패 시의 메시지와 해결 절차를 확인한다.
- 문서에 검증 결과와 남은 제한을 적는다.
- 해당 기능에 필요한 이미지·영상·예제를 준비한다. 아직 없으면 제공 여부를 명시한다.
- 처음 보는 사용자가 문서만 보고 작업을 수행하는지 관찰한다. 막힌 단계를 수정한다.

'한 번에 이해'는 좋은 목표지만 작성자 판단만으로 보장할 수 없다. 사용자 테스트에서 설명을 다시 요구한 지점을 기록하고 개선한다.

## 단계별 확장과 문서

### 1. 실제 CAD 기반
정밀 형상·좌표·단위·안정적 식별자·선택·측정·저장·실행 취소/다시 실행을 마련한다.
스케치·치수·구속·돌출·잘라내기·피처 수정의 실제 수행 절차와 예제를 만든다.
현재의 예제 상자 크기 변경을 완성된 피처 모델링으로 설명하지 않는다.

### 2. 도면과 조립
모델에 연결된 투상/단면/상세도·치수·공차·출력과 부품 배치·조립 구속을 만든다.
모델 수정이 도면·조립에 어떻게 반영되는지 문서와 영상으로 설명한다.

### 3. 금형
구배·언더컷·이형 방향·파팅·코어/캐비티·슬라이드/리프터를 실제 제품 사례로 검증한다.
무엇이 자동이고 사용자가 무엇을 판단해야 하는지 구분한다.

### 4. CAM/NC와 지시서
한 장비·컨트롤러부터 셋업·공구·공정·경로·포스트·NC 출력과 지시서 연결을 검증한다.
NCBrain은 공개 기능 연구의 참고 대상으로 사용한다. 충돌 검사와 시간 절감의 입력·한계·검증 근거를 명시한다.
실제 Excel 양식·조건표를 확보한 뒤 셀 매핑, 단위, 조건 버전, NC 대조, 오류 알림과 갱신 절차를 설명한다.

### 5. 전문 해석·확장
운동·구조·열·사출 등은 각 해석기의 입력, 가정, 라이선스, 결과 해석과 검증을 별도로 갖춘다.
탭이나 버튼만 마련한 상태를 해석 기능 제공으로 안내하지 않는다.

모든 영역은 공통 프로젝트를 참조하며, 형상·NC·조건 변경 시 하위 결과의 갱신 필요 상태를 추적해야 한다.
